# Runbook: key rotation

NFR-S2 (secrets never in the web tier or the repository), FR-I1 AC13 (credential rotation), ARCHITECTURE.md section 15.2 step 2; unit U55 (D80). Owner: Platform and Operations. Every value lives in the team password manager under the environment's name, never in the repository, a ticket or a chat.

Interval (to be confirmed by CHARA): every credential below at least once a year, the same day when a person who held it leaves, and immediately when it may have leaked. Rotate staging first, then production. The order is always: create the new value, put it everywhere it is read in the same minute, verify, then revoke the old value. Record each rotation in the rotation log kept with the release record: date, environment, credential, person, the verification result and the time the old value was revoked.
